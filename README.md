# 경로 일기 (timeline-diary)

구글 타임라인을 올리면 **하루하루 다닌 길이 캘린더에 그려지는 일기장**입니다.
날짜를 누르면 그날의 경로가 지도로 펼쳐지고, 그 아래에 짧은 일기를 남길 수 있습니다.

- 하루 경로를 **한눈에 보기**(SVG)와 **지도에서 재생**(애니메이션) 두 가지로
- **트랙** — 사람마다 남기고 싶은 게 다르니, 그날 무엇을 기록할지 고를 수 있습니다
- 구글 로그인 → 기기 간 동기화
- 로그인 없이도 사용 (이 기기에만 저장). 나중에 로그인하면 쌓인 기록이 그대로 계정으로 합류합니다.
- 업로드한 파일은 **브라우저 밖으로 나가지 않습니다.** 날짜별로 정리한 경로만 저장됩니다.

빌드 도구는 Vite. 런타임 의존성은 지도용 Leaflet 하나뿐이고, **API 키가 필요 없습니다.**
배경지도는 OpenStreetMap을 씁니다.

---

## 1. Vercel 배포

1. [vercel.com/new](https://vercel.com/new) → **Import Git Repository** → `TRASH-TRACO/timeline-diary` 선택
2. 설정은 건드릴 필요 없습니다. Vercel이 자동으로 잡습니다.
   - Framework Preset: `Vite`
   - Build Command: `npm run build`
   - Output Directory: `dist`
3. **Deploy** → 끝. `https://timeline-diary.vercel.app` 같은 주소가 나옵니다.

이후 `main`에 push하면 자동으로 재배포됩니다.

> 이 단계까지만 하면 **로그인 없이 사용하기**는 바로 됩니다.
> 구글 로그인은 아래 2번을 해야 동작합니다.

## 2. Firebase 설정 (구글 로그인용)

이 앱 전용 Firebase 프로젝트 **`timeline-diary-99be8`** 를 씁니다.
설정값은 [`src/firebase-config.js`](./src/firebase-config.js)에 들어 있으니
두 가지만 해주세요.

### 2-1. 승인된 도메인 추가

Firebase 콘솔 → **Authentication → 설정 → 승인된 도메인 → 도메인 추가**

1번에서 받은 Vercel 주소를 넣습니다. 예: `timeline-diary.vercel.app`

> 여기에 없는 도메인에서 로그인하면 `auth/unauthorized-domain` 오류가 납니다.
> 앱이 그 오류를 만나면 해결 방법을 화면에 띄워주니, 안내대로 하시면 됩니다.

### 2-2. Storage 켜기 (사진용)

Firebase 콘솔 → **Storage → 시작하기** → 위치는 Firestore와 같은 곳으로.

만들어지면 **Rules** 탭에 이 저장소의 [`storage.rules`](./storage.rules) 내용을
붙여넣고 **게시**합니다.

> 사진 없이 쓰실 거면 건너뛰어도 됩니다. Storage가 없으면 사진은 **이 기기에만**
> 남고 다른 기기로 넘어가지 않습니다(앱은 그대로 동작합니다).

### 2-3. Firestore 규칙 게시

Firebase 콘솔 → **Firestore Database → 규칙** 탭에 이 저장소의
[`firestore.rules`](./firestore.rules) 내용을 붙여넣고 **게시**를 누릅니다.

로그인한 사람이 **자기 UID 아래 문서만** 읽고 쓸 수 있게 하는 규칙 하나가 전부입니다.
하위 컬렉션은 상위 문서의 규칙을 물려받지 않으므로 `users/{uid}/diary/{monthKey}`
경로를 직접 적어주어야 합니다.

이 세 가지가 끝나면 구글 로그인과 기기 간 동기화가 동작합니다.

## 3. 선택 — 다른 Firebase 프로젝트로 옮기기

프로젝트를 갈아타고 싶으면 Vercel 프로젝트의
**Settings → Environment Variables**에 아래를 넣고 재배포하세요.
코드를 고칠 필요는 없습니다.

| 변수 | 예시 |
|---|---|
| `VITE_FB_API_KEY` | `AIzaSy...` |
| `VITE_FB_AUTH_DOMAIN` | `my-diary.firebaseapp.com` |
| `VITE_FB_PROJECT_ID` | `my-diary` |
| `VITE_FB_STORAGE` | `my-diary.firebasestorage.app` |
| `VITE_FB_SENDER_ID` | `1234567890` |
| `VITE_FB_APP_ID` | `1:1234567890:web:abcdef` |

값은 Firebase 콘솔 → 프로젝트 설정 → **내 앱 → 웹 앱**의 SDK 설정에 있습니다.
[`vercel.json`](./vercel.json)의 리라이트 주소도 같이 바꿔주세요(4번 참고).

> Firebase 웹 설정값은 비밀이 아닙니다. 브라우저에 그대로 실려 나가는 값이고,
> 실제 접근 통제는 보안 규칙과 승인된 도메인이 합니다. 그래서 기본값을
> [`src/firebase-config.js`](./src/firebase-config.js)에 그냥 적어 두었습니다.

## 4. 선택 — 로그인 팝업에 내 도메인 보이게 하기

기본 설정에서는 구글 로그인 팝업 주소창에 `timeline-diary-99be8.firebaseapp.com`이
잠깐 보입니다. 내 도메인으로 바꾸고 싶다면:

1. `VITE_FB_AUTH_DOMAIN`을 내 도메인으로 설정 (예: `timeline-diary.vercel.app`)
2. [`vercel.json`](./vercel.json)의 `/__/auth` 리라이트가 그 요청을 실제 Firebase
   인증 핸들러로 넘겨줍니다. 이미 `timeline-diary-99be8`를 가리키게 들어 있으니
   그대로 두면 됩니다. (3번으로 프로젝트를 옮겼다면 `destination`도 바꿔주세요)

이 리라이트는 기본 설정에서는 쓰이지 않으니, 신경 안 쓰셔도 아무 문제 없습니다.

## 지도 바꾸기

기본은 **Leaflet + OpenStreetMap**입니다. 키도 결제 계정도 필요 없어 설정 없이 돌아갑니다.

지도를 다루는 코드는 [`src/map/`](./src/map) 아래 어댑터로 분리돼 있습니다.
재생 타임라인과 자동 카메라 — 이 앱에서 정작 까다로운 부분 — 는 지도와 무관하므로,
배경지도를 갈아끼워도 그쪽은 그대로입니다.

```
src/map/geo.js       배율 계산 (웹 메르카토르 — 지도 라이브러리와 무관, 브라우저 없이 검증 가능)
src/map/leaflet.js   Leaflet + XYZ 타일  ← 기본
src/map/kakao.js     카카오맵 SDK
src/map/index.js     어느 쪽을 쓸지 고르고, 실패하면 되돌린다
```

### ① 타일만 바꾸기 (가장 쉬움)

VWorld(국토지리정보원)처럼 일반 XYZ 타일을 주는 곳이면 환경 변수만 넣으면 됩니다.
한글 지명·건물 디테일이 OSM보다 낫고, Leaflet을 그대로 쓰므로 **아무것도 깨지지 않습니다.**

| 변수 | 예시 |
|---|---|
| `VITE_TILE_URL` | `https://api.vworld.kr/req/wmts/1.0.0/{키}/Base/{z}/{y}/{x}.png` |
| `VITE_TILE_ATTR` | `© VWorld` |
| `VITE_TILE_MAXZOOM` | `18` |

### ② 카카오맵으로 바꾸기

| 변수 | 값 |
|---|---|
| `VITE_MAP_PROVIDER` | `kakao` |
| `VITE_KAKAO_KEY` | 카카오 개발자 사이트의 **JavaScript 키** |

[developers.kakao.com](https://developers.kakao.com/) → 내 애플리케이션 → 앱 설정 →
**플랫폼 → Web**에 배포 도메인을 등록해야 SDK가 동작합니다.

> ⚠️ **카카오 어댑터는 검증되지 않았습니다.** 개발 환경에서 카카오 도메인이 막혀 있어
> SDK를 불러올 수도, 자동 테스트를 돌릴 수도 없었습니다. 그래서 실패하면 조용히
> OpenStreetMap으로 되돌아가도록 해 두었습니다(이 되돌림 경로는 테스트했습니다).
> 지도가 아예 안 뜨는 일은 없지만, 카카오 쪽은 직접 보시면서 고쳐야 할 수 있습니다.
> 특히 이런 것들이 어긋날 수 있습니다.
>
> - **레벨 ↔ 배율 대응** — 카카오는 레벨(1~14, 작을수록 확대), Leaflet은 배율(클수록 확대)을
>   씁니다. `src/map/kakao.js`의 `LEVEL_BASE`가 근사값이라, 확대 정도가 어색하면 이 숫자만 고치면 됩니다.
> - **어두운 화면** — 카카오는 자체 지도 스타일을 쓰므로 OSM처럼 타일을 반전시키지 않습니다.
>   다크 모드에서도 지도는 밝게 나옵니다.
> - **부드러움** — 카카오에는 flyTo가 없어 중심 이동과 레벨 변경을 따로 겁니다.

> 참고: 끊김의 원인은 지도 라이브러리가 아니라 카메라 로직이었습니다(계측상 Leaflet에서
> 60fps·드롭 0). 지도를 바꾼다고 부드러워지지는 않습니다. 바꿀 이유는 **한국 지도 디테일**입니다.

> OSM 타일은 [이용 정책](https://operations.osmfoundation.org/policies/tiles/)상
> 대규모 트래픽에는 쓸 수 없습니다. 개인용·소규모라면 문제없지만, 사용자가 늘면
> 위 ①이나 ②로 옮기는 게 맞습니다.

## 타임라인 데이터 받는 법

앱 안의 **도움말** 버튼에도 같은 내용이 있습니다.

- **안드로이드** — 설정 → 위치 → 위치 서비스 → 타임라인 → *타임라인 데이터 내보내기* → `Timeline.json`
- **아이폰** — Google 지도 → 프로필 → 타임라인 → ⋯ → 위치 및 개인 정보 설정 → *타임라인 데이터 내보내기* → `location-history.json`
- **Takeout** — [takeout.google.com](https://takeout.google.com/) → *위치 기록(타임라인)* 만 선택, JSON → 받은 `.zip`을 **압축 풀지 말고** 그대로 올리기

### 지원하는 형식

| 형식 | 파일 | 최상위 키 |
|---|---|---|
| 안드로이드 기기 반출 (2024~) | `Timeline.json` | `semanticSegments`, `rawSignals` |
| iOS 기기 반출 (2024~) | `location-history.json` | (배열) |
| 예전 Takeout 시맨틱 기록 | `2021_JANUARY.json` 등 | `timelineObjects` |
| 예전 Takeout 원시 기록 | `Records.json` | `locations` |

좌표 표기(`geo:37.5,127.0` / `37.5665°, 126.9780°` / `latitudeE7` / `latE7` / `{lat,lng}`)도
전부 받습니다. 날짜 분류는 기록에 박힌 UTC 오프셋을 우선 쓰고, 없으면 브라우저
시간대로 환산합니다 — 그래야 자정 근처 기록이 엉뚱한 날로 밀리지 않습니다.

아주 큰 `Records.json`(원시 위치 로그, 수백 MB)은 브라우저가 감당하기 어려워
건너뜁니다. 기기에서 내보낸 `Timeline.json`이나 `Semantic Location History` 폴더의
월별 파일을 쓰면 훨씬 빠르고 결과도 깔끔합니다.

## 트랙 — 그날 무엇을 기록할지

사람마다 남기고 싶은 게 다르고, 종류마다 필요한 화면도 다릅니다.

| 트랙 | 무엇을 받아서 | 어떻게 보여주나 |
|---|---|---|
| 이동 경로 | 구글 타임라인 파일 | 경로 애니메이션 (전용 화면) |
| 이소티논 | 그날 먹은 양 · 사진 · 상태 메모 | 캘린더 배지 · 월 누적 복용량 |

그래서 "무엇을 기록하는가"를 [`public/js/tracks.js`](./public/js/tracks.js)에 **선언으로** 적고,
화면은 그 선언을 보고 그립니다. 새 트랙을 더할 때 화면 코드는 건드릴 필요가 없습니다.

```js
{
  id: 'isotretinoin', name: '이소티논', icon: '💊',
  fields: [
    { key:'dose', type:'number', label:'복용량', unit:'mg', quick:[0,10,20,40] },
    { key:'note', type:'text',   label:'상태 메모', max:200 },
  ],
  cell:    v => v.dose != null && { badge: v.dose + 'mg' },   // 캘린더에 뭘 보일지
  summary: entries => [...],                                  // 월 요약
}
```

필드 타입이 곧 콘텐츠 계층입니다. 지금은 `number`·`text`·`photo`가 있고
`scale`(1~5)·`bool`(했다/안 했다)이 다음 후보입니다.
전용 화면이 필요하면 `view`를 주면 됩니다 — 경로가 그렇습니다.

트랙은 **데이터** 메뉴에서 켜고 끕니다. 끄더라도 이미 남긴 기록이 있는 날에는
계속 보입니다 — 다른 기기에서 켠 걸 몰라서 기록이 사라진 것처럼 보이면 안 되니까요.

## 공개할 때 무엇이 나가는가

헤더의 **공유**에서 기간과 트랙별 공개 수준을 고르고, 그 결과를 그대로 미리 본 다음
JSON으로 내보낼 수 있습니다. (링크로 공개하는 건 아직입니다 — 걸러내는 경로는 같습니다.)

**무엇을 내보낼 수 있는지는 트랙이 스스로 선언**합니다.
[`public/js/share.js`](./public/js/share.js)의 함수는 전부 순수 함수라, 무엇이 새는지
브라우저 없이 검증할 수 있습니다.

공개의 단위는 **필드가 아니라 "기간 × 트랙"** 입니다. 필드마다 스위치를 늘어놓으면
트랙 10개에 스위치 30개가 되어 자기가 뭘 켰는지 아무도 모르게 되고, "사진은 공개,
복용량은 비공개" 같은 뜻이 안 통하는 조합도 생깁니다. 그래서 말이 되는 묶음을
트랙이 미리 선언하고, 사용자는 트랙마다 그중 하나를 고릅니다.

| 트랙 | 공개 수준 |
|---|---|
| 이동 경로 | 요약만 · **집 주변 가리기**(기본) · 궤적 전체 |
| 이소티논 | **복용량만**(기본) · 복용량 + 메모 · 사진까지 |

### 집 주변 가리기

**궤적은 집과 직장 주소를 그대로 드러냅니다.** 이 앱은 심지어 `시작 00:10 · 집`이라고
라벨까지 붙여 줍니다. 그래서 기본값이 가리기입니다.

끝만 자르면 부족합니다 — 낮에 집에 한 번 들르면 그 자리가 궤적 한가운데 남습니다.
그래서 **기준점(시작·끝·집/직장 방문) 반경 500m 안의 점을 전부** 뺍니다.

도려낸 자리는 `breaks`로 표시하고, **그리는 쪽은 반드시 거기서 붓을 뗍니다.**
이어 그리면 잘라낸 자리를 가로지르는 직선이 생겨 가린 의미가 없어집니다.
실측(테스트)으로 끊김을 지키면 집에서 553m까지만 접근하고, 무시하면 **64m**까지
파고듭니다.

> 한계도 적어 둡니다. 양쪽 구간의 방향을 연장하면 교차점에서 대략적인 위치를
> 짐작할 수 있습니다. 반경이 그걸 줄여 줄 뿐 없애지는 못합니다. 같은 방식을 쓰는
> 운동 앱들도 같은 한계를 갖습니다.

### 걸러내는 방식

`projectDay()`는 **"뺄 것을 지우는" 게 아니라 "넣을 것만 넣습니다."** 선언에 없는
필드는 그냥 안 나갑니다. 나중에 트랙에 필드를 추가해도 저절로 새지 않습니다.

발행 전에 **"이게 남들에게 보이는 전부입니다"** 를 보여줍니다. 숫자 요약만이 아니라
걸러진 결과 자체를 그립니다 — 집을 가렸다면 가려진 그림이 나와야 믿을 수 있으니까요.
표본은 내용이 가장 많은 날을 고릅니다(아무 날이나 잡으면 정작 확인하고 싶은 항목이
빠진 날이 걸립니다). 민감한 수준을 고르면 그 자리에서 경고합니다.

사람이 확인할 수 없는 공개는 사고가 납니다.

### 사진

사진은 **기기에 먼저** 담고, 로그인돼 있으면 뒤이어 올립니다. 로그인 없이도 쓸 수
있어야 하는데 Firebase Storage는 로그인이 있어야 쓰기 때문입니다. 못 올린 사진은
목록에 남았다가 로그인할 때 올라갑니다.

올리기 전에 브라우저에서 **긴 변 1600px · JPEG**로 줄입니다. 실측으로
2400×1600 PNG 976KB → 1600×1067 JPEG 29KB. 원본 그대로 두면 한 장에 수 MB라
무료 한도를 금방 먹고 화면에 띄우는 것도 느립니다.

하루 기록에는 사진이 아니라 **id만** 들어갑니다(`photos: ['a1b2…']`).
실제 파일은 이 기기의 IndexedDB와 `users/{uid}/photos/{id}.jpg`에 있습니다.

### 저장 구조

`users/{uid}/diary/{YYYY-MM}` — 한 달에 문서 하나. 로컬(IndexedDB)과 원격이 같은
모양이라 병합 함수를 양쪽에 그대로 씁니다. 설정은 `users/{uid}/diary/settings`에 삽니다.

```js
days: {
  '2024-06-18': {
    note, noteAt,                          // 기본 일기 — 항상
    t: {                                   // 트랙별 기록
      route:        { v: {…}, at: … },
      isotretinoin: { v: { dose:20, note:'…' }, at: … },
    }
  }
}
```

병합은 **날짜 × 트랙별로 최신 우선**입니다. 그래서 A기기에서 약을 기록하고 B기기에서
경로를 올려도 서로를 덮어쓰지 않고, 충돌을 물어볼 일도 없습니다.

경로는 좌표·시각을 정수 델타로 편 뒤 **쉼표로 이은 문자열 하나**에 담습니다.
배열이 아니라 문자열인 이유가 있습니다 — Firestore는 배열 원소마다 색인 항목을
만들고 문서당 4만 개가 상한인데, 하루 300점이면 원소가 900개라 활동이 많은 달은
문서 전체가 거부됩니다. 문자열이면 색인 항목이 1개입니다.
(덤으로 배열 안의 배열을 못 담는 제약도 사라지고 용량도 줍니다)

### 색에 대해

경로 색은 **시간**이라는 하나의 연속량을 나타내므로 단일 색상 램프
(이른 시각 → 늦은 시각) 하나만 씁니다. 무지개로 칠하면 순서가 안 읽힙니다.
시작·끝은 색이 아니라 글자로 구분하고, 라벨은 겹치면 자리를 옮기거나 아예
적지 않습니다. 밝은 화면과 어두운 화면의 램프는 자동 반전이 아니라 각각 따로
골랐습니다.

### 자동 카메라에 대해

하루 전체에 배율을 고정하면 여행 간 날은 도착지에서 걸어다닌 게 점 하나로 뭉갭니다.
그래서 재생 지점을 따라 배율이 같이 움직입니다 — KTX로 이동 중이면 넓어지고,
골목을 걸으면 좁아집니다.

범위는 **기록된 점이 아니라 재생될 경로를 샘플링해서** 잡습니다. 긴 직선 구간은
경로 단순화 때 점 두 개로 줄어들기 때문에, 주변 점을 모으는 방식으로는 그 사이에서
볼 게 없어져 오히려 최대 배율로 확대돼 버립니다.

배율 변화는 언제나 `flyTo`로 갑니다. `setView`의 애니메이션은 CSS 전환이라
`zoomAnimationThreshold`(기본 4)를 넘는 변화를 아예 애니메이션하지 않고 순간이동시키는데,
여행 간 날의 z15→z7 같은 변화가 정확히 거기 걸려 뚝 끊깁니다.

카메라가 움직이는 중인지는 이벤트가 아니라 "언제까지"로 관리합니다. `moveend`로
플래그를 내리면 직전 동작의 `moveend`가 새 비행 직후에 도착해 플래그를 지우고,
그 틈에 팬이 끼어들어 비행을 중간에서 잘라 먹습니다.

마커는 늘 화면 한가운데에 붙어 있고 지도가 그 아래로 흐릅니다(내비게이션과 같은 방식).
예전엔 마커가 가장자리에 닿을 때만 중앙으로 되돌렸는데, 그러면 0.5초마다 화면이 툭 튀어
흔들리는 느낌이 났습니다. 매 프레임 조금씩 흘리면 튀는 순간 자체가 없습니다.

배율이 바뀌는 동안에는 재생 시간을 멈춰 마커를 세워둡니다. 확대와 이동이 겹치면
무엇이 움직이는지 읽기 어렵습니다.

사용자가 지도를 끌거나 확대하면 따라가기가 꺼집니다. 이때 `movestart`/`zoomstart`로
감지하면 안 됩니다 — 우리 카메라가 움직일 때도 똑같이 나고, 재생 중엔 카메라가
600ms마다 움직이므로 "우리가 움직였나" 플래그가 늘 켜져 있어 정작 사용자 조작이
무시됩니다. 그래서 끌기·휠·더블클릭·핀치·확대 버튼만 콕 집어 듣습니다.

### 재생 속도에 대해

하루를 실제 시간대로 틀면 대부분이 정지 화면입니다(집·직장에 머무는 시간).
그렇다고 점 간격을 무시하고 일정 속도로 움직이면 "얼마나 오래 머물렀는지"가
사라집니다. 그래서 구간마다 실제 걸린 시간을 재생 시간으로 쓰되, 한자리에 오래
머문 구간은 전체의 4%까지만 시간을 주도록 눌렀습니다. 머문 티는 나되 화면이
멎지는 않습니다. 표시되는 시각은 눌리기 전의 진짜 시각입니다.
